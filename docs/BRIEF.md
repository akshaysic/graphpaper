# Graphpaper Storybook brief

## Goal
Turn the Graphpaper design system into a React component library with Storybook as its workshop. After Phase 3 this repo is the source of truth; the Claude Design system follows it.

## Source
design/ holds the system as published in Claude Design. Treat it as read-only reference.
- design/tokens.json: every token and type style. The only source of values.
- design/README.md: usage rules. Follow them.
- design/components/bundle.js: the 18 components and 2 hooks as plain React. Port these; do not redesign them.
- design/components/bundle.css: component styles. Copy it unchanged.
- design/components/index.d.ts: props for every component.
- design/components/<Name>/README.md: guidelines. design/components/<Name>/preview.html: the reference rendering and story content.
- design/fonts/Geist-Variable.woff2: the only font (SIL Open Font License).

## Inventory (fixed)

No new components, variants, props or tokens without my written confirmation.

## Stack
- Vite, React 18 (the Claude Design system loads React 18), TypeScript.
- Storybook, current stable release, react-vite framework, accessibility addon, and the test tooling the installed version recommends. Read its docs for the installed version before configuring. Prefer versions published at least two weeks ago.
- No CSS-in-JS, no Tailwind, no UI kit.

## Token compile (scripts/build-tokens.mjs)
Line 1: /* Graphpaper: generated from tokens.json */
1. :root, [data-theme="light"] { every colour token and shadow token, light values }
2. [data-theme="dark"] { dark values; a token without a dark value is not repeated }
3. :root { spacing, radius, duration, easing and opacity tokens; --font-sans }
4. One class per type style: .<name> { font-family, font-size, line-height, font-weight, letter-spacing }
5. One @font-face per font in type.fonts.
A value written "{name}" becomes var(--name). A plain string is the light value. Fail the build on an alias to a missing token.

## Porting rules
- Same DOM, class names and props as bundle.js, so components.css applies unchanged. Types from index.d.ts.
- Type only through the eight style classes. The only font sizes in CSS are the four already in components.css.
- Colours, spacing, radii, durations and easings only through tokens. The nav blend's #fff and #000 are the one exception.
- Reduced motion: hooks read prefers-reduced-motion exactly as bundle.js does. To check by hand, use Chrome DevTools > Rendering > Emulate CSS prefers-reduced-motion. Tests emulate it.

## Stories
- Title "<Group>/<Name>", group from the inventory above. Foundations pages under "Foundations/".
- At most three stories per component, named by state ("Default", "Compact", "Dark band"). Variation through args and controls.
- Story content comes from design/components/<Name>/preview.html. Component description comes from its README.md.
- Toolbar: Theme (light, dark) sets data-theme on the story root with background var(--ground). Stories that sit on a dark band set data-theme="dark" themselves, as the previews do.
- Viewports: 390, 768, 1440.
- Scroll-driven components render inside their own scroll container, as in the previews.

## Public framing
The Storybook is public and linked from akshaygite.com. Its first page, "Read me first", uses this text as written:

  Graphpaper is a design-system study. I took the marketing site for Figma Weave (weave.figma.com) apart and rebuilt its design language as tokens, 18 React components and the motion rules behind its scroll and hover effects. The components use no Figma or Weave names, marks, copy, imagery or fonts.

  What I changed from the source:
  - Type no longer scales with the viewport width, so body text stays at 16px on a phone.
  - Three contrast problems are fixed: white text on the sage footer, the faded headline grey, and list states told apart by hue alone.
  - Every animation respects reduced motion.
  - The system is cut to 8 type styles, 13 colours and 5 spacing steps.

  Built with Claude and Claude Code, directed and reviewed by me.

## Writing rules (docs and story copy)
- No em-dashes or en-dashes as punctuation. Use full stops, commas or colons.
- Banned words: seamless, intuitive, delightful, effortless, empower, leverage, robust, cutting-edge.
- Short sentences. Copy wording from design/ rather than writing new.

## Done means
lint, typecheck, tests and build-storybook pass; no accessibility violations in either theme; each component's first story at 1440 looks like its preview.html in both themes.
